- **未见** `WF-SERIAL-CONSTRUCTION`/`WF-SERIAL-LOG`；`sys_serial_counters` 缺失 → 施工日志序列号文档已过时。

## 二、设计假设逐条验证

| # | 假设 | 结论 | 依据/修正 |
|---|---|---|---|
| B1 | 需新建 `road_lines`/`road_structure_marks`/`road_points_logs` | ✅ 成立 | 库中无任何 road/station 表 |
| B2 | `geofences` 需加 `source`/`road_id` | ✅ 成立 | 现无这两列 |
| B3 | 三条业务表需加桩号列 | ✅ 成立 | `attendance_records`/`location_history` 均无 |
| B4 | 坐标统一 GCJ02 | ⚠️ 部分 | MP/地图=GCJ02；**H5=WGS84**，导入(KML/DXF)通常 WGS84/CGCS2000 → 必须带 `cs` 参数转换 |
| B5 | 无需 PostGIS，纯 JS 计算可行 | ✅ 成立（当前量级） | 无 PostGIS；728+184 行，O(points) 可接受 |
| B6 | `geo.ts` 是扩展点 | ✅ 成立 | 现仅有距离两函数，桩号函数需新增 |
| B7 | `WF-STATION-POINT` 可零侵入接入 | ✅ 成立（需防环） | `script`+`update` 节点可用；但 afterSave→update 同表**有递归风险**（见 C7） |
| B8 | 路线派生围栏可复用现有「折线+buffer」检测 | ✅ 成立 | `pointToSegmentDistance ≤ buffer` 即为特例 |
| B9 | 客户端水印可行 | ✅ 成立（前提） | MP `<camera>`+canvas、H5 getUserMedia+canvas 可行；后端 Sharp 兜底**受限于无 CJK 字体**（见 C10） |
| B10 | `rd_projects` 可作路线归属 | ❌ 不可 | 表 **0 行**且无路线几何 → 路线的 project 归属需允许空/手工指定 |

## 三、设计方案缺陷审计

| # | 缺陷/风险 | 严重度 | 建议 |
|---|---|---|---|
| C1 | **单向 `reverse` 与上下行/匝道多线叠加**：同一点可能最近于多条 line，归属歧义 | 高 | convert 必须支持显式 `road_id`；无显式时按 `project_id + 最近距离 + is_active` 规则并返回候选列表 |
| C2 | **累积里程依赖预计算 `points[].meters`**：仅存 lng/lat 时桩号漂移 | 高 | 路线保存时强制重算累积里程并落库；导入时校验 |
| C3 | **坐标混用**：LOCATION_HISTORY 历史 728 行基准未知，直接算桩号会系统性偏差 | 高 | 加 `cs` 字段/参数；历史数据先抽样反查基准再回填 |
| C4 | **H5(WGS84) vs MP(GCJ02) 双基准**，同一 API 结果不同 | 高 | `station/convert` 必须强制 `cs`；服务端统一转 GCJ02 后计算 |
| C5 | **`geofences` 派生 upsert 可能覆盖手工围栏** | 中 | `source='road'` 命名空间 + 按 `road_id` 幂等写；手工围栏 `source='manual'` 不动 |
| C6 | **派生围栏遗漏 bbox 维护** | 中 | 路线保存时同步写 `bbox_*`，否则检测预筛失效 |
| C7 | **工作流递归**：afterSave→script→update 同表会再次触发 afterSave | 高 | update 前置守卫：`station` 已存在则跳过；或改 `action` 触发 |
| C8 | **桩号双源不一致**：客户端算 + 工作流算 | 中 | 定 **服务端为权威**，客户端仅显示 |
| C9 | **`station_offset_m`/前缀/负桩号**格式未定 | 中 | 明确 `K12+350` 规则、负偏移、`prefix`（如 `K/ZK/YK`）与结构物返回 |
| C10 | **后端水印兜底无 CJK 字体** | 高 | 若启用后端水印必须先装字体并打进镜像 |
| C11 | **结构物区间重叠/同桩号多结构** | 中 | `road_structure_marks` 返回数组，按包含关系选择 |
| C12 | **导入坐标顺序**：GeoJSON/KML 均为 `[lng,lat]`，易与 lat/lng 反 | 中 | 导入层强校验范围（lng 73~135，lat 3~54） |
| C13 | **字段命名不一致**：新列需按各自表惯例（location_history 用 snake_case） | 低 | 建表时对齐所在表风格 |
| C14 | **性能**：每条 GPS 触发一次 convert | 低 | 批量/批量 API；必要时索引 `road_id` |
| C15 | **ACL/资源注册**：`__pd__` 端点鉴权链需覆盖新端点 | 中 | 复用 MP token 校验；convert 建议 loggedIn 或 apiKey，禁匿名 |
| C16 | **AGENTS 工作流约束**：本地 src 可能滞后于服务器 | 中 | 先 `sync-from-server.ps1` 拉齐，改在服务器→验证→拉回→提交 |

## 四、结论与下一步

- 设计主体**可行**，但有 5 个高危项（C1/C2/C3/C4/C7/C10）必须在 P0 前定稿。
- 修正 B10：路线归属**不强依赖 `rd_projects`**（空表）。
- 修正施工日志序列号文档：`sys_serial_counters` 与 `WF-SERIAL-*` 已不存在，需重新确认现行编号机制。

**P0 交付顺序建议**
1. 定 `cs` 契约与坐标基准（C3/C4）
2. 建 `road_lines`/`road_structure_marks`/`road_points_logs`（含累积里程）
3. 扩展 `geo`：`projectToSegment`/`nearestOnPolyline`/`stationToStr`/`strToStation`
4. `GET /api/__pd__/station/convert`（带 `cs`）
5. 路线派生围栏 upsert（命名空间+bbox）
6. `WF-STATION-POINT`（带防环守卫）
